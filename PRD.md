# PRD - Sirah Nabawi Daily Telegram Bot (FINAL)
## Version: 2.1
## Stack: Google Apps Script + Google Sheets + Telegram Bot API

---

# 1. PROJECT OVERVIEW

This project is a Telegram bot that delivers daily micro-stories from the Sirah Nabawi of Prophet Muhammad ﷺ.

It uses a real dataset:
- sirah_bot_database_v2_200plus.csv (200+ Sirah micro-stories)

Each user receives:
- 1 Sirah story per day
- at user-selected time
- sequentially (not random)
- automatically via scheduler

---

# 2. OBJECTIVE

Build a system that is:
- Free (Google ecosystem only)
- Scalable (1000+ users)
- Simple (beginner friendly)
- Automated (no manual sending)
- Consistent (daily engagement)

---

# 3. CORE PRINCIPLE

IMPORTANT DESIGN RULES:

- NO external server
- NO complex infrastructure
- ONE global scheduler only
- SEQUENTIAL storytelling (last_index system)
- MINIMAL Google Apps Script quota usage
- BATCH processing for users

---

# 4. SYSTEM ARCHITECTURE

Telegram Bot
   ↓
Google Apps Script (Logic Engine)
   ↓
Google Sheets (Database)
   ↓
Sirah Dataset CSV (200+ entries)

---

# 5. DATASET

Source file:
- sirah_bot_database_v2_200plus.csv

Columns:
- id
- fase
- cerita
- hikmah
- refleksi

Usage:
- Imported into Google Sheets (SIRAH sheet)
- Used sequentially per user

---

# 6. GOOGLE SHEETS DESIGN

## USERS SHEET

| user_id | chat_id | preferred_time | last_index | status | created_at |

Description:
- user_id = Telegram ID
- chat_id = Telegram chat ID
- preferred_time = "07:00"
- last_index = last sent sirah index
- status = active / paused

---

## SIRAH SHEET

| id | fase | cerita | hikmah | refleksi |

Source:
- Imported from CSV dataset

---

## LOGS SHEET

| user_id | sirah_id | sent_at | status |

Purpose:
- prevent duplicate sends
- debugging
- tracking delivery

---

# 7. USER FLOW

## /start
- Register user
- Ask preferred time

Message:
"Jam berapa kamu ingin membaca Sirah setiap hari? (contoh: /jam 7)"

---

## /jam {hour}
Example:
- /jam 7
- /jam 19

System:
- store preferred_time = "07:00"
- confirm to user

---

## /status
- Show progress:
  - last_index
  - percentage completion

---

## /stop
- Pause bot (status = paused)

---

## /lanjut
- Resume bot (status = active)

---

## /ulang
- Send last Sirah again

---

# 8. DELIVERY ENGINE (CORE LOGIC)

Scheduler runs every 1 minute:

FOR each user in USERS:

IF:
- status == active
- current_hour == preferred_time
- user has remaining Sirah

THEN:
1. Get next Sirah (last_index + 1)
2. Send message via Telegram API
3. Update USERS.last_index
4. Write to LOGS

---

# 10. SCALABILITY REQUIREMENTS

Must support:
- 1000+ users minimum
- execution under 10 seconds per cycle
- batch processing only
- minimal API calls

Optimization rules:
- getValues() once per sheet
- update in batch
- avoid per-user API calls to Sheets

---

# 11. ERROR HANDLING

System must:
- retry Telegram API (max 2 times)
- skip invalid chat_id
- log failures in LOGS
- prevent duplicate messages

---

# 12. SECURITY

- BOT_TOKEN stored in Script Properties
- validate webhook origin
- ignore unknown commands safely
